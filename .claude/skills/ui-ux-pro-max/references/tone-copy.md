# Tone & copy

All user-facing strings are English (changed from Turkish in the 2026-08-13
redesign — this includes strings generated by `mentor_core.py` that flow
into the GUI, like the low-confidence/fallback caveat labels, since a
mixed-language UI would look unfinished). This file is the style guide for
writing new ones consistently with what's already in `scripts/gui_app.py`.

## Register

- Informal but not casual — no exclamation points, no emoji, no "please."
- Lowercase, terse status words: `"loading..."`, `"thinking..."`,
  `"ready"`. Not sentences, not capitalized. New status states follow this
  same terse lowercase style (`"saving..."`, not `"Please wait, saving..."`).
- Ellipsis (`...`) marks an in-progress/ongoing state. A completed state is
  a single word with no ellipsis (`"ready"`).

## Existing strings (for exact matching / consistent voice)

| String | Context |
|---|---|
| `"IT Mentor AI"` | Window title / header |
| `"loading..."` | Status while model loads |
| `"thinking..."` | Status while generating an answer |
| `"ready"` | Status once ready/idle |
| `"Ask"` | Submit button label |
| `"Something went wrong: {exc}"` | Generic error, rendered as an answer |
| `"Loading search index..."` / `"Loading tokenizer..."` / `"Loading base model..."` / `"Model ready."` | `mentor_core.load()`'s progress callbacks, shown in the status label |

## Disclaimer

`DISCLAIMER_TEXT` is a single, persistent, always-visible small-font label
(see `references/components.md`) — NOT a one-time chat message anymore. It
was deliberately **shortened** during the redesign (the original three-
sentence Turkish version took up too much vertical space in the chat
transcript). Current text:

> "Personal project, not an official resource - answers may be inaccurate.
> Verify before critical actions."

This is intentionally terser than before, but still keeps the substance
that matters: not an official source, accuracy isn't guaranteed, and the
user should verify before anything critical. If rewording, keep it to
roughly this length (short enough to sit on one or two lines at 9pt) —
don't let it grow back into a paragraph, and don't drop the "verify before
critical actions" part even to save space. This matters specifically
because the model answers sysadmin/IT questions (cron, iptables, systemd,
PowerShell, etc.) where a wrong answer could cause real damage.

## RAG caveat labels (`mentor_core.py`, shared with the CLI)

These aren't written in `gui_app.py`, but they render inside the GUI's
answer text, so they follow the same English-only rule:

| String | When shown |
|---|---|
| `"(Closest match found - may not be exact)"` | Medium-confidence RAG match |
| `"(No solid data on this topic - attempting a general answer, don't trust this without verifying)"` | No good RAG match, falling back to the base model for a genuine (non-casual-chat) question |

Changing these affects `scripts/test_model.py` (the CLI) too, since both
share `mentor_core.answer_question()`. That's intentional — see
`06_Decisions_Log.md` for the decision to keep the whole pipeline in one
language rather than splitting GUI/CLI copy.

## Errors

Errors are shown inline as a normal answer (`f"Something went wrong:
{exc}"`, rendered via `_add_answer` — same styling as any other model
response), not a popup/messagebox, and not translated further — the raw
exception message is appended as-is after the English prefix. Keep this
pattern for new error paths: a short English prefix explaining *what*
failed, followed by the raw underlying detail, so a technical user (this
app's actual audience) can still diagnose it.

## New copy checklist

1. English, lowercase for status fragments, sentence case for full
   sentences (the disclaimer).
2. Terse over polite — no "please," no exclamation points, no emoji.
3. Status verbs end in `-ing...` for in-progress, plain adjective/noun for
   done (`ready`), matching the pattern already used.
4. If the new copy is generated in `mentor_core.py` (shared with the CLI),
   remember it affects `test_model.py`'s output too — that's expected, not
   a bug to work around.
